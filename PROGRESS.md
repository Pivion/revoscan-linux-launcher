- AppImage public-payload audit passed. Ubuntu 22.04 Xvfb launcher smoke passed. Debian 12 container smoke created a 64-bit Wine prefix and started the GUI, but emitted missing host Vulkan/display warnings because the test container had no graphics driver.
- Current tests: 23 Python unit tests and the C GPU-property-map test suite pass.
- Fixed the Pop!_OS Revo Scan no-window failure (0.1.2). Root cause: Wine's `winebth.sys` Bluetooth driver exposes the host BlueZ radio to Wine prefixes; Revo Scan's `simpleble.dll` then calls WinRT `BluetoothAdapter::FromIdAsync` / `DeviceInformation::CreateFromIdAsync`, which Wine still implements as `E_NOTIMPL` stubs (verified against Wine master). The `winrt::hresult_not_implemented` exception escapes `rvscan` plugin activation (CTK rethrows `ctkRuntimeException`), the app dies before showing its window, and a Crashpad dump records `0xe06d7363`. Fedora only "worked" because it had no Bluetooth radio. Radio-less behaviour is now enforced deterministically: the AppImage build strips `winebth.sys`/`winebth.so` from the bundled Wine, and the launcher's `sanitize_bluetooth` removes any staged `winebth.sys` plus the `Services\winebth` / `Enum\winebth` registry sections from existing prefixes before installer/launch. Verified on Pop!_OS 24.04 (COSMIC Wayland, RX 580) with the shipped 0.1.2 AppImage: a deliberately re-dirtied prefix was sanitized and Revo Scan 6.4.1.1088 launched with the full UI (1280x720 X11 window `IsViewable`, screenshot captured; `Scan plugin started` and all 15 plugins started; app logs `BluetoothManager init error` and continues). Bluetooth/BLE scanner discovery is therefore not available under this build until upstream Wine implements `DeviceInformation::CreateFromIdAsync`; WLAN-connected scanners are unaffected. Evidence preserved under git-ignored `local/pop-debug/`. New tests: `tests/test_bluetooth.py` (3); suite is now 26 Python unit tests plus the C suite.

## In progress

- Resolve/characterize the Fedora 44 container WineBoot smoke timeout and test on a full Fedora desktop with host graphics libraries.
- Investigate the Revo Scan no-window failure on Pop!_OS. Fresh-prefix runs under bundled Wine 11.0, system Wine 9.0, and manual Wine Staging 11.0 reproduce it. Live `+seh` evidence shows a `winrt::hresult_not_implemented` exception whose RTTI is in `simpleble.dll` during plugin activation, followed by a generic `ctkRuntimeException` (`ctkPlugin start failed`). `simpleble.dll` contains Windows C++/WinRT Bluetooth initialization code, and `rvscan.dll` exposes Bluetooth-manager initialization. I initially treated this as causal, but the working Fedora log also records `BluetoothManager init error` despite no Bluetooth adapter and later proceeds to POP4 streaming. A GDB breakpoint also hit CTK's generic `ctkPlugin start failed` catch-all constructor, whose overload does not retain an inner exception. The preceding SimpleBLE/WinRT `hresult_not_implemented` is therefore correlation, not proof of cause; the fatal `rvscan` startup cause remains unknown. Ghidra confirms `ScanPlugin::start` logs `Scan plugin started` only at its end, and Pop logs stop immediately after `Starting plugin: rvscan`. The app never sends a show/map request for its top-level window. `rvcore` provides the camera-manager service queried by `rvscan` and starts first, so simple missing-service ordering is not supported. Bundled-Wine Notepad maps normally. Forced X11, virtual desktop, software OpenGL, and X11 remapping did not produce usable UI; forced mapping yielded black. No reliable workaround is confirmed. Environment comparison: the AppImage SHA-256 matches on both hosts (`b12e8444387dd0336dafcefc62f76f2705b654d1d4971ce1f76ee3ff3e310d4c`). Fedora is Ultramarine 44/KDE Wayland, kernel 7.2.9, Mesa 26.2.4, Xwayland 24.1.14, Radeon 780M; Pop is 24.04/COSMIC Wayland, kernel 7.1.5, Mesa 26.1.6, Xwayland 24.1.13, RX 580. The launcher inherits host variables; Pop session processes export `QT_QPA_PLATFORM=wayland;xcb` and `GDK_BACKEND=wayland,x11`, unlike Fedora's session. A disposable-prefix run with the Pop `QT_QPA_PLATFORM` value still failed at `rvscan`; X11 window creation varied between runs, so this variable is not isolated as the cause. The user's systemd user-manager environment points to XRDP X11 `DISPLAY=:10.0`, while the COSMIC Wayland session is `:1`. Under identical Wine 11/prefix/environment except `DISPLAY`, `:1` starts the OpenGL 3+ renderer and reaches `rvscan`; `:10.0` stops in `MainWindow::initVisualMgr`. Its `ogre.log` ends after OpenGL subsystem creation, and the Wine trace reports `X Error: BadValue` from `XFree86-VidModeExtension` request `XF86VidModeSetGamma`. This strongly implicates the XRDP gamma-ramp path for launches on `:10.0`; the exact caller is not yet identified. The `:1` run still has a separate `rvscan` activation failure. In the disposable prefix, setting Wine `HKCU\\Software\\Wine\\X11 Driver\\UseXVidMode` to `REG_SZ N` on `:10.0` removed the `XF86VidModeSetGamma` BadValue, let Ogre start OpenGL 3+, and let `rvcore` start; `rvscan` still failed to complete and no usable window appeared. The test value was deleted and verified absent. This confirms the XRDP gamma error is one environment blocker, not the whole fix. A related xorgxrdp report documents the same BadValue request: https://github.com/neutrinolabs/xorgxrdp/issues/271. **RESOLVED (2026-10-17, see Accomplished): the root cause was Wine's `winebth` Bluetooth driver exposing the host BlueZ radio; removing it from the bundled runtime fixed the failure.**

## Known issues and limitations
- Fedora 44 container testing timed out during WineBoot; this is not a pass. openSUSE and Arch are untested.
- The Debian 12 test had no Vulkan driver; it cannot validate GPU mapping or scanning.
- Intel-to-AMD identity mapping is unverified on physical Intel hardware. A successful identity-filter check does not guarantee compute support.
- No complete Revo Scan scan/fusion/export has been completed. The Pop!_OS no-window failure was root-caused and fixed in 0.1.2: Wine's `winebth` Bluetooth driver exposed the host BlueZ radio and Revo Scan's `simpleble.dll` hit still-stubbed WinRT Bluetooth APIs (`E_NOTIMPL`) during `rvscan` plugin activation, killing the app before its window mapped; the build now strips the driver from the bundled Wine and the launcher sanitizes prefixes. Bluetooth/BLE scanner discovery does not work under this build until upstream Wine implements `DeviceInformation::CreateFromIdAsync` (Wine master still stubs it); WLAN-connected scanners are unaffected. The XRDP gamma `XF86VidModeSetGamma` BadValue on `DISPLAY=:10.0` (https://github.com/neutrinolabs/xorgxrdp/issues/271) is a separate environment blocker for XRDP sessions; launches on the COSMIC Wayland session (`:1`) work.
- The final AppImage is a preview build, not a published release. It uses the host graphics stack and device permissions.
